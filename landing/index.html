How it fits together

One small server between your code and the EIA. REST and MCP share the same validated core.

Type-safe, from query to response

The server's types flow straight into your client. No codegen, no hand-written interfaces.

import { treaty } from '@elysiajs/eden'
import type { App } from './src'

const api = treaty<App>('localhost:3000')

const { data, error } = await api.query.post({
  domain: 'coal',
  route: 'aggregate-production',
  frequency: 'annual',
  data: ['production'],
})

// typed, autocompleted
data?.response.data[0]

// domain: 'nope' is a compile error
// and a 422 at runtime

Requests

Bodies are validated at runtime and typed from the same TypeBox schema.

Responses

Normalized EIA responses with typed errors — no more guessing at upstream shapes.

Schemas that match reality

Domains, routes, facets and frequencies are discovered from the live EIA metadata.

Errors

429s are backed off and retried; everything else surfaces as a typed error.

Documented automatically

The OpenAPI spec is generated from the same schemas, so it can't drift from the code.

# start the API, then open the docs
bun dev
http://localhost:3000/openapi       # Swagger UI
http://localhost:3000/openapi/json  # OpenAPI 3.1
# generate a client in any language
bunx openapi-typescript spec.json -o api.d.ts
bunx @openapitools/openapi-generator-cli \
  generate -i spec.json -g python -o ./client

Examples with a purpose

Discover first, then query. Every endpoint is plain HTTP.

# search by topic
curl -X POST localhost:3000/search \
  -H 'content-type: application/json' \
  -d '{"q": "solar"}'
# → domains, routes, tags, example queries
# filter by facet
curl -X POST localhost:3000/query \
  -H 'content-type: application/json' \
  -d '{"domain":"electricity","route":"retail-sales",
       "frequency":"monthly","data":["price"],
       "facets":{"stateid":["TX"],"sectorid":["RES"]}}'
# list domains / fetch the agent playbook
curl localhost:3000/domains
curl localhost:3000/guide
# run the bundled examples
bun run examples/02-discovery.ts
bun run examples/06-query-post-basic.ts
bun run examples/agent-usage.ts

Quick start

Install, configure, query.

# run it
bun install
cp .env.example .env
# set EIA_API_KEY in .env
bun dev   # http://localhost:3000
# discover, then query
curl localhost:3000/domains
curl -X POST localhost:3000/query \
  -H 'content-type: application/json' \
  -d '{"domain":"coal","route":"aggregate-production",
       "frequency":"annual","data":["production"]}'
