All server configuration is via environment variables. Copy `.env.example`
to `.env` and edit.

## Variables

| Variable | Default | Purpose |
|---|---|---|
| `EIA_API_KEY` | `DEMO_KEY` (required when `NODE_ENV=production`) | Upstream EIA API key (held server-side) |
| `EIA_BASE_URL` | `https://api.eia.gov` | Upstream EIA API base |
| `PORT` | `3000` | Server port |
| `LOG_LEVEL` | `info` | `debug` \| `info` \| `warn` \| `error` |
| `EIA_MIN_INTERVAL_MS` | `5000` | Min spacing between outbound EIA fetches (`0` disables) |
| `MCP_ENABLED` | `false` | Mount `/mcp` (Model Context Protocol) |

## Per-variable guidance

### `EIA_API_KEY`

The most important setting.

- **`DEMO_KEY`** — works without signup but is heavily throttled.
- **Real key** — free at [eia.gov/opendata/register.php](https://www.eia.gov/opendata/register.php).

Required when `NODE_ENV=production`: the server refuses to start without it.

The key is held **server-side** only. Clients talk to `localhost:3000`
(or your public proxy) and the key never leaves the server.

### `EIA_MIN_INTERVAL_MS`

EIA doesn't publish its limits; third-party reports put them around **5
requests per second** in bursts. The wrapper enforces this with a per-process FIFO queue: every outbound EIA call
is spaced by at least `EIA_MIN_INTERVAL_MS` milliseconds.

- **`5000`** — safe default.
- **`1000`** — tighter, still under the limit.
- **`0`** — disables the limiter (only safe with a paid-tier EIA key).

Upstream `429` responses are **not** retried. Instead the wrapper pauses all
EIA traffic for the response's `Retry-After` (60s if absent), and callers get
`429` with `Retry-After` straight away instead of adding to the load. A request
that would wait more than 60s in the queue gets `503` with `Retry-After`
rather than hanging, and queued requests whose client disconnects are dropped
without calling EIA. GET and POST responses are cached, and identical
concurrent requests share a single upstream call.

<Aside type="caution">
  The queue, pause and cache are **per process**. Two replicas (or the
  server plus a stray `bun dev`) each run their own queue, so EIA sees twice
  the rate. Run a single instance, or raise `EIA_MIN_INTERVAL_MS` in
  proportion to the replica count.
</Aside>

### `MCP_ENABLED`

Set to `true` to mount the [MCP](/mcp/overview/) endpoint at `/mcp`. Off
by default. When enabled, the same MCP endpoint is also documented in the
OpenAPI spec.

### `LOG_LEVEL`

- **`debug`** — every upstream call, cache hit/miss, rate-limiter spacing
- **`info`** — default; one line per request
- **`warn`** — only warnings and errors
- **`error`** — only errors

## Verifying

After editing `.env`, restart the server:

```bash
bun dev
```

You can confirm the new config is loaded via:

```bash
curl http://localhost:3000/version
# { "server": "0.1.0", "eiaApi": "2.1.0" }
```

A failed upstream lookup (e.g. wrong `EIA_BASE_URL`) shows up as `upstream:
"degraded"` on `/health`.
